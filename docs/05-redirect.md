# 5. Перенаправление колонки на мост

Все адреса Яндекса прописываются в `/etc/hosts` самой колонки и ведут на контейнер. Роутер не трогаем. Колонка читает этот файл раньше своего DNS-резолвера, и правка переживает перезагрузку (корневой раздел без dm-verity). Почему именно так, см. [architecture.md](architecture.md#почему-etchosts-а-не-dns-роутера).

## 1. Остановите стенд lite-kit

Он держит порты 80 и 443:

```bash
pkill -f lite-kit; pkill dnsmasq; sleep 1
ss -tlpn | grep -E ':(80|443)\b'   # если остался python — kill <pid>
```

## 2. Пропишите адреса

Файл [station/hosts](../station/hosts) — итоговый `/etc/hosts` колонки. Замените в нём `192.168.1.49` на IP вашего моста, затем:

```bash
ssh -p 2222 root@192.168.1.102 'mount -o remount,rw /'
scp -P 2222 station/hosts root@192.168.1.102:/etc/hosts
ssh -p 2222 root@192.168.1.102 'sync; mount -o remount,ro /; cat /etc/hosts; reboot'
```

## 3. Уберите ненужный сторож

Если раньше ставили `S98zlocal` (дописывал адреса в конфиг unbound, который тот не перечитывает), удалите его:

```bash
ssh -p 2222 root@192.168.1.102 'mount -o remount,rw / && rm -f /etc/init.d/S98zlocal; sync; mount -o remount,ro /'
```

## Проверка

Запустите мост вручную или службой ([часть 6](06-service.md)). После перезагрузки колонки в логе моста появятся `check_updates`, `get_sync_info` и `WS подключение`. На «Алиса, который час?» — строки `ASR: 'Который час'` и `HA: … -> '10:58'`.

`nslookup` на колонке показывает настоящие адреса Яндекса: он `/etc/hosts` игнорирует. Проверяйте по логу моста.
